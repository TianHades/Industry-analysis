# 行业分析报告契约与模板 v3.0

> **本文件是报告的唯一规范（single source of truth）**：orchestrator、各子技能、校验器都以此为准。
> **执行流程**：草稿写入 `output/_drafts/` → 运行 `python tools/validate_report.py` → P0 全过才发布到 `output/`。
> **旧模板（v2.x，10 模块）已废止**；历史报告已移除，不提供向后兼容。

---

## 0. 硬性契约摘要（校验器逐条检查）

| # | 契约 | 校验方式 |
|---|------|----------|
| R1 | 报告头 YAML metadata 齐全、日期自洽 | `validate_report.py` E-META-* |
| R2 | 固定 8 个一级章节 + 14 个固定编号模块，顺序不可变 | E-STRUCT-* |
| R3 | 估值表（投资者版）≥5 家、代码/PE 或 PB/来源/获取时间列齐全，获取时间 = data_cutoff | E-VAL-* |
| R4 | 报告数值必须与 `output/_data/` 取数 JSON 一致 | E-VAL-CROSS |
| R5 | 🟢 只用于实际数据（行内不得含预测词）；🟡 必须标注预测年份 | E-MARK-* |
| R6 | 若质量说明声称"含文件编号"，全文必须至少一处 `〔YYYY〕` 文号 | E-LIE-* |
| R7 | 表格中"增速/同比"必须与相邻两期数值自洽 | E-MATH-GROWTH |
| R8 | "PE 中位数"等汇总值必须由表内数值复算一致 | E-MATH-MEDIAN |
| R9 | 第二曲线：成熟期须实质论证（≥200 字，不得只写"不适用"）；衰退期须论证或"不适用+理由"（≥100 字）；导入/成长期可"不适用+理由" | E-MOD-14 |
| R10 | 假设模块 ≥3 条假设，每条含验证指标与证伪条件 | E-MOD-04 |
| R11 | 禁止把修订记录/版本日志/自检自述写进正文（自检由 check.json 生成） | W-BODY-REVLOG |
| R12 | 投资者版至少 1 个行业指数/板块涨跌信号 | E-STRUCT-INDEX |

> **默认身份/受众**：未指定时 `identity: 投资者`，叙事按大老板（R→S→C→Q，结论前置）；用户明确其他身份/受众时切换。

## 1. 报告头（YAML frontmatter，必须出现在文件第一行）

```yaml
---
schema: report-v3
industry: 白酒
identity: 投资者                # 默认；可选：创业者 / 求职者 / 学生（学生/研究者） / 路人
generated_at: 2026-10-20        # 报告生成日
data_cutoff: 2026-10-17         # 数据截止日（估值取数日必须等于此日）
valuation_fetch_date: 2026-10-17  # 投资者版必填；非投资者版可省略
template_version: 3.0
orchestrator_version: 3.0.0     # 与 industry-analysis-orchestrator/SKILL.md 的 version 一致
lifecycle_stage: 成熟期          # 导入期 / 成长期 / 成熟期 / 衰退期
penetration: "62%"              # 渗透率（可写 null）；必须写明口径
evidence_files:
  - output/_data/白酒-valuation-20261017.json
  - output/_data/白酒-facts.json
---
```

规则：
- `generated_at >= data_cutoff`；投资者版 `valuation_fetch_date == data_cutoff`。
- `evidence_files` 中每个文件必须真实存在（相对仓库根目录），否则校验失败（数据不可追溯）。
- `identity` 决定报告叙事顺序（见 `identity-oriented-output`）与估值表最低家数（投资者 5 家，其他 3 家）。
- `lifecycle_stage` 决定模块 10 / 14 的填写要求。

## 2. 固定结构

一级章节（顺序固定）：

```
## 📋 执行摘要
## 🎯 对{身份}的核心结论          ← 必须含"风险提示"与"机会点"两个子节
## ✅ AI 已完成的分析             ← 以下 14 个模块必须齐全、编号严格递增
## 🚀 建议下一步行动
## 🔍 可继续深入的研究方向
## 📚 完整信源列表
## 📝 数据时效性与质量说明        ← 校验器在此节注入"自动校验"行
## ⚠️ 免责声明
```

14 个模块（`### N. 标题`，编号与顺序不可改；可加子标题 `####`）：

| # | 模块 | 何时必须实质展开 | 关键要求 |
|---|------|------------------|----------|
| 1 | 行业定义与边界 | 所有报告 | 标准定义 + 分类归属 + 与相似行业区分 |
| 2 | 产业链结构 | 所有报告 | 上游/中游/下游 + 各环节参与者与利润分配 |
| 3 | 产业生命周期判断 | 所有报告 | 渗透率数值 + 口径 + 阶段判断依据 |
| 4 | 核心假设与验证条件 | 所有报告 | ≥3 条假设，每条含验证指标、证伪条件、当前状态 |
| 5 | 时空对标 | 所有报告 | ≥1 个时间对标 + ≥1 个空间对标 + 终局判断 |
| 6 | 商业模式分析 | 导入期/成长期深度，成熟期可简要 | 画布要素 + 可行性判断 |
| 7 | 市场规模测算 | 导入期/成长期深度，其余可简要 | TAM/SAM/SOM 三口径齐全，公式与来源明确 |
| 8 | 护城河分析 | 成熟期深度，其余可简要 | 最相关 2–3 类 + 可绕过性检验 |
| 9 | 竞争格局与利润分配 | 成熟期深度 | CR3/CR8 + 产业链利润分配 + TOP 企业 |
| 10 | 产能周期与库存周期 | 成熟期/周期型行业深度 | CAPEX/折旧 + 库存水位；非适用须写"不适用 + 理由" |
| 11 | 估值逻辑 | 所有报告 | 阶段匹配方法 + 估值表 + 偏低/合理/偏高 + 预期差 |
| 12 | PEST 外部驱动 | 所有报告 | P/E/S/T 四维齐全，各维 ≥1 因素 + 来源 |
| 13 | 景气度跟踪与验证方案 | 所有报告 | 3–5 个指标 + 验证/证伪条件清单 |
| 14 | 第二曲线扫描 | 成熟期强制；衰退期必查；导入/成长期可选 | 结论 + 量级/增速/脱钩程度；不适用须写理由 |

**阶段深度规则**（分析深度，不影响模块存在）：导入期重点 4/6/7；成长期重点 7/14（可选）；成熟期重点 8/9/10/14；衰退期重点 14 + 11（估值陷阱）。

## 3. 符号与数据标注（与 `data-annotation-standards.md` 一致）

| 符号 | 含义 | 机器规则 |
|------|------|----------|
| 🟢 | 实际数据（官方/财报/已发生） | 行内不得出现"预测/预计/预期/估算/目标" |
| 🟡 | 预测数据 | 行内必须出现 4 位年份 |
| 🟠 | 历史数据（需注意时效） | 建议标注年份 |
| 🔴 | 不确定/无权威来源 | 必须在质量说明中解释 |
| 🔍 | AI 推断/手动估算/未核实 | 不得用于估值表的实时数值 |
| 🔒 | 需人工或专业工具 | 用于能力边界声明 |
| ⏳ | 待量化（后续必须闭环） | 每条须在模块 4/13 有验证安排 |

统一行内格式：`数值（来源，年份）`，如 `市场规模 2.64 万亿元（国家统计局，2025 年）`。

## 4. 估值表（模块 11）硬性格式

```markdown
#### 🔴 投资者版核心标的估值数据表（实时数据，{valuation_fetch_date} 收盘；盘中/午间快照须在表前注明）

| 标的 | 代码 | 最新价 | PE(TTM) | PB | 总市值(亿元) | 股息率 | 数据来源 | 获取时间 |
|------|------|--------|---------|-----|--------------|--------|----------|----------|
| 贵州茅台 | 600519 | 1500.00 | 25.5 | 8.1 | 19000.0 | 2.5% | 雪球 | 2026-10-17 |
```

规则：
- 投资者版 ≥5 家；其他身份 ≥3 家。
- 单元格不得出现"待补/未获取/失败/待查"；取不到就标"亏损"或"—"并在质量说明解释，且该行不计入有效家数。
- `获取时间` 每行必须等于 `valuation_fetch_date`；`数据来源` 不得为空。
- 数值必须来自 `evidence_files` 中的取数 JSON；校验器逐值比对（缺失即 P0）。
- 亏损标的 PE 标"亏损"，改用 PS，并注明 PS 计算依据。
- 若快照为盘中/午间（非收盘），须在表前注明"{valuation_fetch_date} 盘中/午间快照"，并在质量说明中说明；不得把盘中价称为收盘价。

## 6. 发布流程（orchestrator 第四阶段）

```bash
# 1) 草稿
#    output/_drafts/{行业}-行业分析报告（{身份}版）.md
# 2) 校验（P0 全过才发布）
python tools/validate_report.py "output/_drafts/{...}.md" \
    --data-dir output/_data --publish-dir output
# 3) 产物
#    output/{...}.md           ← 发布版（含"自动校验"行）
#    output/{...}.check.json   ← 机器校验结果（交付附件）
```

- 校验失败：按 P0 逐条修复后重跑；P1 警告须在质量说明中回应或修复。
- 自检结论**不得手写**，以 `check.json` 为准。
- 报告不得包含修订记录/版本日志（写进 commit message 或 check.json 即可）。
