# 数据标注与时效校验标准（v3.0）

> 本文件被 orchestrator、各子技能与 `tools/validate_report.py` 共同引用，定义统一的数据标注、时效校验、冲突仲裁规则。
> 机器校验规则以 `reference/output-template.md` 的「硬性契约」为准。

---

## 1. 数据来源标注格式

**统一使用行内标注格式**：

```
市场规模 1 万亿元（来源：艾媒咨询，2025 年预测）🟡
渗透率 25%（来源：国家统计局，2024 年实际）🟢
```

**符号体系（唯一权威定义）**：

| 符号 | 含义 | 使用条件 | 机器规则 |
|------|------|----------|----------|
| 🟢 | 实际数据 | 官方统计、企业财报、已发生事件 | 行内不得出现“预测/预计/预期/估算/目标” |
| 🟡 | 预测数据 | 机构预测、模型推算、目标值 | 行内必须出现 4 位年份 |
| 🟠 | 历史数据 | 需注意时效性的旧数据 | 建议标注年份 |
| 🔴 | 不确定数据 | 缺乏权威来源、无法交叉验证 | 必须在「数据时效性与质量说明」中解释 |
| 🔍 | AI 推断/手动估算 | 模型推算的中间值、无法直接获取的数据 | 不得用于估值表的实时数值 |
| 🔒 | 需人工/专业工具 | 能力边界声明（如 DCF 精算、实地调研） | 无 |
| ⏳ | 待量化 | 尚未量化的假设 | 必须在模块 4/13 有对应验证安排，不得静默沉睡 |

> 旧文档中出现的 🔒/🔍 用法不统一，自 v3.0 起以上表为准；报告无需解释符号定义（符号本身即规范）。

---

## 2. 数据时效校验规则（硬性门槛）

**所有数据必须通过时效校验：超过硬阈值默认丢弃；确需使用历史/滞后数据时按下方例外规则标注并说明。**

| 数据类型 | 最大容忍 | 示例 | 处理 |
|---------|----------|------|------|
| 股价/市值/PE/PB/股息率 | **= 报告 data_cutoff**（最后交易日） | 2026-10-16 收盘 | 过期丢弃；必须来自取数 JSON |
| 市场规模/产量/用电量 | **≤ 2 年** | 2026 年报告可用 2024–2026 | 2023 及之前丢弃 |
| 渗透率/CRn/市占率 | **≤ 2 年** | 格局变化快 | 2023 及之前丢弃 |
| 政策法规 | **≤ 3 年** | 未被废止可用，标注年份 | 2022 及之前标 🟠 |
| 行业定义/分类标准 | **≤ 5 年** | 国标修订慢 | 2020 之前需确认最新版 |
| 企业年报/财报 | **≤ 1.5 年** | 最近一个完整财年 | 过期丢弃 |
| 机构预测数据 | **标注预测年份** | “2025 年预测” | 无来源或年份丢弃 |

**执行规则**：
- 搜索关键词加年份限定（如 `2025 2026`）；提取数据时立即核对年份。
- 例外（优先于硬阈值）：最新数据不可得时，用 🟠 标注“最近可用数据为 {年份}”并在质量说明解释；系统性缺口最多放宽 1–2 年，且同一缺口须用 🔴 说明；政策法规硬阈值为 3 年，重要政策超出须单独说明依据。
- 估值数据统一由 `tools/fetch_valuation.py` 取数，报告不得手抄或二次换算（校验器逐值比对）。

## 3. 数据冲突仲裁规则

同一指标多来源不一致时，按优先级采信：

```
① 官方统计（国家统计局/部委/行业协会）
② 上市公司财报（经审计）
③ 权威行业报告（艾媒/智研/IDC/欧睿等）
④ 券商研报
⑤ 媒体报道
⑥ 自媒体/社区
```

同优先级内：年份最新 > 口径明确 > 实际数据 > 预测数据。

处理方式：
- 差异 < 20%：取权威最高来源的值，标注“另有来源显示约 {其他值}”。
- 差异 ≥ 20%：两个值都列出，说明口径差异，用 🔍 标注。
- 单一来源：标注“单一来源，未交叉验证”。

## 4. 报告质量自检（v3.0：自动校验 + 人工复核）

**自动校验（必须通过，P0 不得有）**：

```bash
python tools/validate_report.py "output/_drafts/{报告}.md" --data-dir output/_data
```

覆盖：报告头 metadata、8 个一级章节、14 模块结构与编号、估值表（≥5 家/来源/获取时间/无占位符/与 JSON 逐值一致）、符号规则、政策文号声明、增速/中位数算术、第二曲线范围、假设与验证条件、行业指数信号。

**人工复核（自动校验无法覆盖）**：

- [ ] 产业链结构、假设、验证条件等内容的**业务合理性**（是否真的可验证、是否与结论一致）
- [ ] 数据口径是否与结论匹配（存量/增量、含税/不含税、产量/销量）
- [ ] 事实判断与价值判断是否区分（价值判断须有事实支撑）
- [ ] 是否搜索并呈现了反面观点
- [ ] 关键结论是否为“提炼”而非“总结”（包含“那又怎样”的增量）
- [ ] 推理链是否自洽（PEST 修正是否回馈到基本面/估值，见 orchestrator 修正回路）
- [ ] 报告不包含修订记录/版本日志/手写自检结论（自检以 `{报告}.check.json` 为准）
